# Nonamebtww Shop

Мобильное приложение интернет-магазина одной компании (не маркетплейс) для iOS и Android. Покупатель выбирает товары в каталоге, собирает корзину, оформляет и оплачивает заказ, а сотрудники магазина ведут каталог, распределяют заказы по курьерам и доставляют их.

Проект учебный: дисциплина «Информатика», ВГТУ, вариант 5 «Интернет-магазин». Это прототип (MVP), поэтому сервера нет. Все данные лежат в локальной базе SQLite на устройстве, а платёжная система, SMS и почта заменены заглушками.

## Возможности

Покупатель:

- регистрация по email или по номеру телефона с подтверждением кодом, вход по логину, почте или телефону, восстановление пароля;
- каталог с поиском, фильтром по категории и цене, флажком «Только в наличии» и сортировкой;
- карточка товара с фотографиями, характеристиками и отзывами, оценка товара от 1 до 5;
- избранное и корзина;
- оформление заказа: курьером, срочно курьером, самовывоз или постамат; оплата картой или через СБП (заглушка);
- список заказов («Активные» и «Завершённые»), отмена заказа с возвратом денег;
- профиль: личные данные, устройства, смена пароля, уведомления, удаление аккаунта.

Сотрудники (раздел «Профиль → Панель сотрудника»):

| Роль | Что может |
|---|---|
| Менеджер по продажам | ведёт каталог: товары, категории, цены, остатки, фото |
| Логист | назначает курьеров на оплаченные заказы |
| Курьер | принимает заказ в доставку, отмечает «Вручён» или «Не вручён» |
| Владелец | всё перечисленное, а также меняет роли и блокирует пользователей |

Покупать могут все роли: после входа любой пользователь попадает в каталог.

## Технологии

- .NET 10, .NET MAUI 10 (iOS 15+, Android 6.0+ / API 23)
- ReactiveUI.Maui (MVVM), FFImageLoading.Maui (загрузка и кэш картинок)
- Entity Framework Core 10 + SQLite
- Иконки HeroIcons

## Структура решения

| Проект | Назначение |
|---|---|
| `Nonamebtww.Shop.Domain` | сущности и правила предметной области: агрегаты «Заказ», «Товар», «Пользователь» и др., статусы заказа и допустимые переходы между ними |
| `Nonamebtww.Shop.Application` | сценарии использования (каталог, корзина, заказы, доставка, профиль, администрирование), DTO, проверка ввода |
| `Nonamebtww.Shop.Infrastructure` | EF Core и SQLite, демо-данные, хэширование паролей, сессия, заглушки платежей и уведомлений, см. [README](Nonamebtww.Shop.Infrastructure/README.md) |
| `Nonamebtww.Shop.Mobile` | приложение MAUI: страницы, ViewModel, навигация Shell |
| `Database` | SQL-скрипты базы для SQLite и PostgreSQL с тестовыми данными, см. [README](Database/README.md) |

Mobile вызывает сценарии Application через интерфейсы `I*Api`. В прототипе их реализуют локальные классы, которые работают прямо с базой SQLite на устройстве.

## Установка

Понадобятся:

- .NET SDK 10;
- workload MAUI: `dotnet workload install maui`;
- для iOS: macOS и Xcode с симулятором iOS;
- для Android: Android SDK и эмулятор (ставятся вместе с Android Studio или Visual Studio).

Клонирование и сборка:

```sh
git clone https://github.com/nonamebtww/Nonamebtww.Shop.git
cd Nonamebtww.Shop
dotnet restore
```

Запуск в симуляторе iOS (на Mac):

```sh
dotnet build Nonamebtww.Shop.Mobile -t:Run -f net10.0-ios
```

Запуск в эмуляторе Android (эмулятор должен быть уже запущен):

```sh
dotnet build Nonamebtww.Shop.Mobile -t:Run -f net10.0-android
```

Можно открыть `Nonamebtww.Shop.sln` в Visual Studio или JetBrains Rider и запустить проект `Nonamebtww.Shop.Mobile`. Собирать в конфигурации Debug.

При первом запуске приложение само создаёт файл `shop.db3` в папке данных приложения и заполняет его демо-данными: 32 товара, категории, отзывы и пользователи.

## Использование

На экране входа есть блок «Демо-аккаунты прототипа». Нажатие на строку подставляет логин и пароль.

| Логин | Пароль | Роль |
|---|---|---|
| buyer | Buyer123! | Покупатель |
| manager | Manager123! | Менеджер по продажам |
| owner | Owner123! | Владелец |
| logist | Logist123! | Логист |
| courier | Courier123! | Курьер |

Короткий сценарий, чтобы пройти заказ целиком:

1. Войти как `buyer`, добавить товары в корзину, нажать «Оформить заказ», выбрать «Курьером», заполнить адрес и оплатить.
2. Выйти и войти как `logist`: «Профиль → Панель сотрудника → Распределение доставки», назначить курьера.
3. Войти как `courier`: «Мои доставки», нажать «Принять заказ в доставку», затем «Вручён».
4. Снова войти как `buyer`: заказ лежит во вкладке «Завершённые».

Письма, SMS и коды подтверждения никуда не отправляются. Они появляются в разделе «Профиль → Уведомления» и во всплывающих сообщениях.

Подробная инструкция для каждой роли находится в руководстве пользователя (отдельный документ к лабораторной работе №8).

## Конфигурация

Настройки задаются в `Nonamebtww.Shop.Mobile/MauiProgram.cs` при вызове `AddInfrastructure`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `DatabasePath` | `<AppData>/shop.db3` | путь к файлу базы |
| `SeedDemoData` | `true` | заполнять пустую базу демо-данными |
| `RecreateDatabaseOnStartup` | `false` | удалять базу при каждом запуске |
| `DeclinePayments` | `false` | заглушка оплаты отклоняет все платежи, чтобы проверить ошибку оплаты |
| `FakeApiLatency` | 150 мс | искусственная задержка ответов, чтобы были видны индикаторы загрузки |

Схема базы создаётся без миграций. Если модель данных изменилась, удалите приложение с устройства или включите `RecreateDatabaseOnStartup`.

## База данных

16 таблиц: пользователи, роли, устройства, коды подтверждения, категории, товары, отзывы, корзины, избранное, заказы, позиции заказа, платежи, доставки и др. Скрипты создания, тестовые данные и проверочные запросы лежат в папке [`Database`](Database/README.md).
